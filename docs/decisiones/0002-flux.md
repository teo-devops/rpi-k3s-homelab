# 0002 · Flux como motor de GitOps

- **Estado**: Aceptada
- **Fecha**: 2026-11-16

## Contexto

Queremos que todo lo que corre en el clúster esté descrito en Git y se aplique solo. Memoria limitada,
especialmente en la Pi de 2 GB.

## Decisión

Flux CD, con secretos cifrados con SOPS + age.

## Alternativas consideradas

| Opción | A favor | En contra |
|--------|---------|-----------|
| Flux | Ligero (~200-300 MB), todo son recursos de Kubernetes, integra SOPS de forma nativa | Sin interfaz gráfica propia (ver [0007](0007-headlamp-como-ui.md)) |
| Argo CD | Interfaz gráfica excelente, muy usado en empresas | Más pesado (~500 MB o más) |
| Helm + Makefile | Lo más fácil de entender al principio | No es GitOps: nada corrige las desviaciones ni registra qué se aplicó |
| Rancher Fleet | Lo usa uno de los repos de referencia | Requiere Rancher, demasiado pesado aquí |

## Consecuencias

- La estructura de `kubernetes/` sigue la convención de Flux (`clusters/`, `infrastructure/`, `apps/`).
- Para ver el estado hay que usar la CLI (`flux get all`), Headlamp o los dashboards de Grafana.
